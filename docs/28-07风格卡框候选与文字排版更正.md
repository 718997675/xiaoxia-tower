## 1. 核实结论：不是「卡框不够漂亮」，是整套卡面体系对不上了

把 07 原稿单卡放大 3×、整卡预览与网页三选一实拍三者并排比对，得到两条独立缺陷：

| # | 现象 | 根因 |
|---|---|---|
| A | 上半深墨插画 / 下半宣纸米色大块空白，中间还有几条横线 | 第 39 轮把 84×56 插画换成 `#12161F` 墨底，但卡框仍用 `docs/12` §2 的宣纸底冻结卡面。07 原稿是**整卡深墨底**，不是「深插画 + 浅卡身」。横线是旧框自带的占位/分隔线，被误读成「排版乱」 |
| B | 描述里 `20%` 被拆成 `2` / `0%`，「可」「伤害」「命」单字独占一行，底部 `灵品 ×1 · res` 被裁 | 旧 `wrapText()` 按**字符数**硬切；CSS `white-space:pre-line` 又按容器宽度自动折一次，两次折行叠加；`.cname` / `.cdesc` / `.cinfo` 三档字号、坐标贴边，信息条超出卡面 |

结论：**卡框要按 07 重绘，但重绘的是「整卡深墨体系 + 分区结构」，不是给旧宣纸框加花纹**；文字排版则是验证层的真实缺陷（R48 的旧债），与卡框一并修。

## 2. 07 原稿单卡结构（重绘依据）

对 `previews/ui/07-codex-gpt-image2_original.png` 四档单卡逐档放大后的共同结构：

1. **整卡深墨底**，1px 黑硬边 + 1px 稀有度色内圈细线；四档只换线条颜色，结构完全一致。
2. **四角卷云回纹**（左上 / 右上 / 左下 / 右下）。
3. **顶部卡名条**：略亮色带 + 上下细线；左侧小类别纹样；右上角菱形 / 圆形阶角标（1–4）。
4. **插画区**：独立 1px 内凹细边，深墨底，主体居中留白。
5. **效果描述**：插画下方 2 行浅色文字，左对齐，无横线、无框。
6. **底部信息条**：独立色带 + 上下分隔线 + 左侧 `◆` 菱形 + 短标签（如 `灵气+1`）。

四档色：凡品灰蓝 / 灵品青玉 / 仙品金 / 劫品朱红。本轮全部取 `tools/snap_ui_palette.py` 的锁定板，未新增颜色。

### 3.2 网页验证层双模式 + 文字排版修复

`tools/build_web_demo.py`：

- 内嵌 4 张候选框（`codex_frame_*`，与冻结 `frame_*` 并存），内嵌图 316 → **320**。
- **默认 `?frame=codex`** 展示 07 候选；`?frame=frozen` 或「卡框：07 候选」按钮一键切回 `docs/12` 冻结框并排对照。URL 同步用 `history.replaceState`，`file://` 下失败也不影响切换。
- 07 模式 CSS：整卡 `#12161F`、卡名移到顶部条（x14/y3，11px）、描述 x6/y79 三行 12px 行高、信息条 x18/y119，字号统一；类别纹样对齐卡名条 8×8 位；框内已画菱形阶角标，故隐藏旧 `.pips`。
- **`wrapText()` 重写**（修 B 的三个根因）：
  1. token 化（汉字 / 全角标点 / 英文单词 / `数字%` 各成整体），开括号与后一词绑定，避免行尾悬挂；
  2. `canvas.measureText` 用与 `.cdesc` **完全相同的字体**按真实像素累加到 84px 再折行，不再靠「汉字 1 / ASCII 0.5」估算（该估算会低估 `<20%` 导致末字被裁）；
  3. CSS 改 `white-space:pre` + `overflow:hidden`，**折行只由 JS 决定**，不再二次自动折行；超出 3 行按像素回退到能容纳 `…` 的位置。
  4. 信息条按 07「◆ 灵气+1」的克制口径改为短标签 `凡品 ×1`，不再塞稀有度 + 类别 + 堆叠导致裁切。
- 两种卡框模式**共用同一套折行**，对照只比卡框本身，不把旧排版乱当成对照项。
