## 2. 生产链路（可复现）

```
① 出图  → 文生图，2×2 多格动作条（一张图内保证帧间一致性，远优于分别生成 4 张）
          prompt 必须写死：方形像素块 / 硬边 / 无抗锯齿 / 无平滑渐变 / 少量色阶 /
          纯白底 / 限定 24 色板 / no text no numbers no grid lines
② 目检  → 看图；不像就改 prompt 重生成，最多 2–3 轮
③ 规整  → 切片 → 四角 BFS floodfill 去白底 → NEAREST 缩放到 64×64 →
          24 色板吸附 → 透明硬边
④ 合成  → 精灵图 / GIF / 放大预览 / 引擎 JSON
⑤ 质检  → 数值质检脚本，>=80 SHIP / 60-79 FIX / <60 REDRAW
⑥ 目检成品 → 交付
```

**复现命令**（需 Python + Pillow；本机默认 `python3` 无 PIL，`/opt/homebrew/bin/python3` 自带 Pillow 12.3，换环境请先自检 `python3 -c "import PIL"`）：

```bash
python3 tools/regularize_sprites.py \
  --source assets/_source/<人物源图>.png --kind char \
  --prefix char_player --names idle_r_00 idle_r_01 idle_r_02 cast_r_00 \
  --out assets/char --preview-out assets/_preview --fps 6

python3 tools/regularize_sprites.py \
  --source assets/_source/<特效源图>.png --kind vfx \
  --prefix vfx_sword_qi --names 00 01 02 03 \
  --out assets/vfx/frames --preview-out assets/_preview --fps 12
```

脚本本身是**过程资产**：它把「怎么把 AI 出图变成引擎能吃的素材」固化下来，换账号后照跑即可。

## 3. 质检结论（含一次口径纠错）

| 对象 | 判定 | 证据 |
|---|---|---|
| 人物 idle 3 帧（最终） | ✅ **100 分 SHIP** | bbox 稳定在 `(14,0,49,62)` 附近，位移 ≤2px |
| 人物 idle 3 帧（修正前） | ⚠️ 65 分 FIX | 帧间 bbox 位移 8–11px、第 3 帧居中失败 |
| 特效 4 帧（逐帧） | ✅ **全部 100 分 SHIP** | alpha 半透明像素 0、孤立噪点 0、居中偏移 ≤0.01 |
| 特效 4 帧（带 `--frames` 一起跑） | ❌ 20 分 REDRAW | **口径误判，见下** |
| 调色板越界色 | ✅ **0** | 8 帧全部吸附到 24 色板内，单帧用色 3–17 色 |
| 尺寸 / 硬边 | ✅ | 8 帧均 64×64、`semi_alpha_px=0`、NEAREST 无平滑 |

### 两个必须记住的诊断（换账号别重踩）

**① 人物：统一裁剪框反而放大漂移。**
源图 4 格里的角色位置本身不齐（第 2 格偏左 8px），按「所有格 bbox 并集」统一裁剪会把这个布局误差带进成品。
**正解**：逐格按自身 bbox 裁剪 → 所有帧共用**同一个缩放系数**（按最高帧算）→ 强制水平居中 + 脚底对齐到 y=62。修正后 3 帧 bbox 几乎完全重合。

**② 特效：帧间守恒类质检规则不适用。**
`mass_conservation`（内容量守恒）与 `bbox_stability` 是给**角色循环动画**设计的。剑气特效本来就要从火花长成大弧再消散，opaque 像素 `88 → 404 → 768 → 980` 正是标准递进，却被判「波动 1014% / REDRAW」。
**正解**：特效按**逐帧单帧质检**（4 帧均 100 SHIP）；只有角色循环动画才跑 `--frames` 帧间检查。不要为了迎合判定而把特效改成大小不变。

## 5. 从样板到全量（剩余工作量）

| 目标 | 本批 | 全量规格 | 缺口 |
|---|---|---|---|
| 人物帧 | 4（1 角色，idle+cast 各 1 段） | **75 帧**（5 角色 × 15 帧） | 71 帧、4 个新角色、run/hit/death 动作 |
| 特效帧 | 4（1 技能） | **28 帧**（4 技能 × 6 + 4 命中）或程序化 2 张贴图 | 24 帧或改走 Q18 程序化方案 |
| 图标 | 0 | 40–60 件 | 全缺 |

**批量复制方法**：每 4 帧为一批，沿用「2×2 动作条 → 规整脚本」链路；同角色不同动作要**共用同一张基准图做图生图**（而非各自文生图），否则服饰会漂移。每批跑一次质检 + 目检再入库。

**不要一次铺满 103 张**：AI 逐帧直出的帧间一致性撑不住全量，必须分批、每批目检。这也是本轮只做样板的原因。

**Q18 提醒**：如果最终选程序化特效，这 28 帧序列帧就不需要了，本批 4 帧只作为视觉参考；参数化粒子能直接服务 4 流派 × 12 词缀的差异，更贴合 30 h 的耐玩目标。

**第一次目检返工**：怪物源图 4 帧动作递进太弱（第 1/3 帧雷同）。改 prompt 强制「直立 / 耸肩 / 深蹲压低 25% / 大幅前扑伸爪」后达标。返工版与弃用版都保留在 `assets/_source/` 作过程证据。

**质检**：新 8 帧逐帧质检全部 **100 分 SHIP**；怪物 idle 2 帧循环质检 100 分 SHIP；全项目 16 帧均 64×64 RGBA、半透明 0、24 色板越界色 0、脚底锚点 y=62 统一。成品目检通过（四帧轮廓递进清楚、前扑爪完整、丹火白核恢复）。

**三个新诊断（都已修进脚本，别重踩）**：

| # | 现象 | 根因 | 正解 |
|---|---|---|---|
| 3 | 前扑帧 bbox `(0,10,64,62)` 左右贴边、爪被切、动作被压扁 | 统一缩放系数只按「最高帧」算；`nw = min(nw, 64)` 又只压宽度破坏等比 | `char_scale = min((64-2×2)/max_w, (64-2)/max_h)`，并加等比收缩兜底；修正后 `(2,22,62,62)` |
| 4 | 丹火第 3 帧中心出现**黑洞**，白核消失 | `remove_white_bg` 二次清理全图删 `min>=235` 近白像素，把内部亮核一并删掉 | 只删**紧贴已透明区域**的近白抗锯齿像素；另加 ≤2px 孤立连通域清理去掉 AI 杂点 |
| 5 | 批量重跑生成 4 个**带空格文件名**，4 组引擎 JSON 被覆盖成 `frameCount=1` | **zsh 默认不做单词分割**，`--names $var` 被当成 1 个参数 | 批量调用写**显式帧名**；已清理误产物并重跑恢复 4 帧 |
