## 3. 战斗规则内核 `tools/battle_sim.js`

浏览器与 Node **共用同一份实现**（IIFE + `module.exports` + `window.BattleSim`），网页内嵌的是文件全文，不是「照着另写一遍」：

- **确定性**：FNV-1a 种子 + xorshift32（与 `card_rules.js` / `CardDeck.gd` 同口径）+ 固定 tick `1/30 s`，与浏览器帧率无关。
- **M1 状态机**：IDLE / CASTING / DODGING / DEAD，CD 内重复输入忽略、灵力不足不施法、无敌帧忽略伤害、DEAD 忽略全部输入；同帧输入按 `dodge > skill > move` 取一次。
- **伤害**：`clamp(round((base×realm + pool)×combo×crit×(1−defense)), 1, 9999)`，变量先钳到五上界；`9999` 兜底在五上界下不可达（最坏 3996）。
- **卡牌联动**：`syncDeck()` 只取 `CardDeck.offenseState()` 的 `extra_pool + offense_pool_used + combo_multiplier`，再钳到 600 / 2.5，**不新开数值池**。
- **事件队列**：`cast_started / vfx_requested / damage_applied / player_hurt / shake / enemy_death / boss_phase / stage_cleared / run_ended`，UI 每帧 drain 后渲染。

> 与 Godot 的关系：**Godot 侧目前没有战斗逻辑**，因此本轮不存在「网页 ↔ Godot 战斗黄金样本」。跨端黄金样本仍只覆盖卡牌规则（第 19 轮 25/25）。战斗内核的确定性只在网页 / Node 两端自洽（44 项断言），不得据此声称 Godot 战斗已实现。

## 5. 数值口径：冻结 vs PROPOSAL（最重要的一节）

| 类别 | 内容 | 状态 |
|---|---|---|
| **冻结，不得改** | 五上界 `base≤180 / realm_ratio≤1.60 / extra_pool≤600 / combo≤2.5 / crit≤1.8`、Boss 4400、9 层 HP_total 与 P_dps 波形、`01` §8.1 伤害公式、72 张卡库与抽卡规则 | ✅ 本轮一个未改；`final_selfcheck.py` 新增常量断言防回归 |
| **PROPOSAL 占位（R51）** | 技能 CD / 灵力消耗 / 玩家 HP / 灵力体力回复 / 敌人伤害 / 敌人攻击间隔 / 暴击率 / 闪避无敌时长 / 移动速度 / 施法硬直 / 连击增减 | ⚠️ `01` 策划案**未给这些值**，仅用于让网页演示有节奏；全部集中在 `battle_sim.js` 的 `PROPOSAL` 常量并标 `proposal: true`，**待设计确认，不构成平衡结论** |
| **人造演示输入** | 「🧪 共享池 +150」按钮 / `?pool=N` | ⚠️ 明确标注「不是抽到的卡、不改卡库与冻结数值」，仅用于展示伤害公式对 `extra_pool` 的敏感度；点「重置本层」即复原 |

**关于「选卡后战斗变强多少」的诚实口径**：按冻结规格**卡牌不得提高五上界**，卡库里只有 5 张数值型卡（`card_jianfeng / card_danbao / card_zhanxing / card_zhongzhu / card_shuangren`），共享池增量仅 10–30 点；其余机制型卡（命中数 / 落点 / 贯穿 / CD）的 hook **本验证层未实现**（见 `docs/15` 边界）。因此战斗中能看到数值型卡的小幅变化，**看不到机制型卡的效果**——这是已知边界，等正式战斗工程接 hook 才有，不能写成「卡牌系统已可玩」。

面板里的「峰值 3996」是**五上界最坏口径**，不是当前实战单次伤害；实战飘字按当前 `base / pool / combo / defense` 实时计算。

## 7. 本轮抓到并处置的真实缺陷

| 编号 | 问题 | 处置 |
|---|---|---|
| R53-a | `battle_sim.js` 的 `tick()` 把「`skills` 数组存在」当成「按了技能」，全 false 时吞掉 move → 玩家永远走不动（第 2 层实测只挨打不攻击） | 改为 `skillIdx >= 0` 才进技能分支；`verify_battle_sim.js` 增防回归断言（44 项里的一条） |
| R53-b | 无头 Chrome 虚拟时间下 `requestAnimationFrame` 只跑一帧，自动演示规则不推进 | 自动演示的规则推进改 `setInterval` 驱动固定 tick，rAF 只渲染；两条路径由 `battleAuto` 互斥 |
| R53-c | 演示 AI 把治疗优先级放太高，陷入「治疗→挨打→再治疗」死循环 | 改为攻击优先、仅无攻击机会且血 <40% 才治疗 |
| R53-d | 主菜单立绘未设 `src`（破图）；飘字堆积成团；Boss 血条压住层数文字 | 接 idle 帧循环；同屏最多 5 个飘字 + 确定性错位；血条下移到 top 44px |
| 口径修正 ×2 | 首轮 Node 断言把「五上界后 9999 兜底可达」与「无连续 3 关上升」写错 | 改为「五上界先钳变量，9999 不可达」与「连续上升次数 ≤2」，均照 `01` §8.1/§8.3 复算 |

> 首轮 43 项断言曾 FAIL 2 项，均为**断言口径写歪**而非内核错误，已如实保留在本表，不抹掉。

## 9. 怎么点 / 怎么复跑

**看效果**（不需要 Godot）：双击 `previews/web-demo.html`。

- ⓪ 主菜单：点「▶ 开始入塔」进 ①；或「⚡ 直接看第 9 层 Boss（占位素材）」。
- ① 横版战斗：「▶ 自动演示战斗」一键打到清层；也可自己按 `A/D` 移动、`J/K/L/I` 放技能、`Space` 闪避、`Esc` 暂停。
- 清层后点「🎴 去选一张卡」→ ② 选卡 → 自动回 ① 下一层；想直观看参数影响就点「🧪 共享池 +150」。
- ⑤ 看板：17 项浏览器内实时自检（第 21 轮新增 4 项效果断言）+ 轮次时间线 + 风险表 + 导入前清单。
- **第 21 轮新增**：① 点「🧪 预置机制卡组（演示注入，非抽卡）」或用 `?cards=card_poyun,card_huti,...` 直接预置指定卡，右侧「本局生效卡牌效果」逐卡列出生效条目 / 口径提示 / 未映射理由，战斗日志出现多段命中、护盾吸收、复活等事件（详见 `docs/18`）。

**调试 URL 参数**（仅网页验证层，不影响玩法）：`?battle=N` 直接进第 N 层自动演示；`?freeze=TICK` 停在指定 tick 便于截图；`?autolink=1` 自动跑选卡闭环；`?pool=N` 等价于演示注入；`?autorun=1` 自动跑 ② 的 8 层三选一。

**复跑命令**（均从工程根目录执行）：

```bash
python3 tools/verify_battle_sim.py          # 44/44，写 docs/battle-sim-report.json
python3 tools/build_web_demo.py             # 重建单文件网页
python3 tools/build_web_demo.py --check     # 产物一致性
python3 tools/final_selfcheck.py            # 全量静态自检
python3 tools/verify_cross_platform.py      # 卡牌跨端 25/25（回归）
Godot --headless --path . --script res://tools/verify_card_rules.gd   # 23/23（回归）
```
