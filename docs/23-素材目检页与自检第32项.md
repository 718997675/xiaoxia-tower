## 2. 新增交付

### 2.1 `tools/build_asset_overview.py` → `previews/asset-overview.html`

- 126993 字节，**108 张 PNG 全部内嵌 base64**：Boss 42 + 技能/命中 36 + overlay 10 + 背景 16 层 + 4 合成图。
- `file://` 双击即开，零网络请求、零外部依赖（JS 已过 `node --check`）。
- 交互：① 四个场景切换 + L1–L4 逐层开关叠加 + 2× 放大 + 只看合成图，旁列 L1 暗像素 / 战斗区 R22 代理 / L4 占比 / 每层 coverage 与越界色；② 两个 Boss 帧表逐帧播放；③ 9 组技能特效（8 技能 + 命中）；④ 5 组 overlay；⑤ 机器体检表 + **6 条明确标红的「仍需人工目检 / 待实测」**。
- 页面顶部横幅直接写明：验证层不是游戏本体、程序化 0 积分、R55、`status = 待目检与合规确认`、Q17 / F5 未过、Q24 运行时仍走 shader、视差系数 PROPOSAL。
- `--check`：生成到内存与磁盘逐字节比对，防「改了生成器没重建」。

### 2.2 修正的真实缺陷（不是文档润色）

`tools/build_bg_layers.py` 给 L1/L2/L3 铺底色时用了 `rect((0, 0, W, L1_END))` 等坐标，而 **Pillow `rectangle` 的右/下边界是包含的**，于是 L1 多占 y=68（L2 首行）、L2 多占 y=202（L3 首行），四层叠加时无法满足 `docs/20` §2.3「沿水平线独立切图」。本轮把三个底色矩形下边界改为 `L1_END-1 / L2_END-1 / H-1`，高层场景山影多边形底边也同步收到 `L1_END-1`。

- 生成器新增 `BANDS = {"L1": (0,68), "L2": (68,202), "L3": (202,270)}`，`metrics()` 逐像素统计 `bandStrayPixels`，汇总 `bandStrayTotal` 写进 `docs/bg-layers-report.json`。
- L4 是覆盖在最上层的前景剪影，按设计可跨 L2/L3 带，**不参与此判据**，由 `l4AreaRatio < 10%` 单独约束。
- 复算结果：`bandStrayTotal = 0`；四场景 L1 暗 0.025–0.085、战斗区暗 0.007–0.039（全 LOW）、L4 占比 0.028–0.060，越界色 / 半透明均 0。

### 2.3 `final_selfcheck.py` 第 32 项 `assets_r29`

判据全部**动态自洽**，不写死张数（沿用第 18 轮 `traceability` 与第 29 轮 `c_qc` 的口径）：

1. 两份报告越界色 / 半透明为 0、`bandStrayTotal == 0`、L4 <10%、战斗区暗 <30%、4 场景 × 4 层。
2. 实际 PNG 数 == 报告声明 / `qc-report.json` 中 vfx 各组 `frameCount` 之和；背景图数 == 层数 + 合成图数。
3. 每组引擎 JSON `frameCount == len(frames)`、帧文件齐全、`status` 仍是「待目检与合规确认；不得直接入库」。
4. 每场景层清单尺寸 480×270 / 4 层、四层 PNG + 合成图齐全、状态未被改写。
5. 目检页 script 标签 / 占位符 / 内嵌图数（= Boss + vfx + overlay + 层 + 合成图）/ 无机器绝对路径。
6. 三个生成器 `--check` 全部返回 0（防回归 + 复算像素指标）。

> `final_selfcheck.py` 顶部声明「零第三方依赖」，故像素级检查放在带 Pillow 的生成器里，本项只核对报告并代跑 `--check`，**没有**把 Pillow 引入自检脚本。
