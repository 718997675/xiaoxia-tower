## 0. 这一轮解决什么

第 20 轮用户提出「先做主菜单和战斗横版界面，不然 demo 页面只能看到选卡，战斗效果也看不到」。
当轮交付了六视图与横版战斗，但**机制型卡选中后仍只有一句「hook 未在本验证层实现」**：
`previews/web-demo.html` 里只有带 `extra_pool / base_damage / pool / combo_multiplier` 的数值型卡
会改变共享池，而卡库 72 张里 **17 张纯数值 / 20 张混合 / 35 张机制**，多数卡选了看不见变化。

第 21 轮把它补上，做法是：**只读冻结卡库，把卡面 text 与 params 对得上的参数编译成
`battle_sim.js` 可消费的 EffectSet**，让多段命中 / 破防 / 护盾 / CD / 灵力 / 减伤 / 复活等
在战斗日志与右侧面板里逐条可观测；对不上或条件不满足的，**如实列为未映射，不猜数值、不伪造效果**。

> ⚠️ **本轮仍然是网页验证层**。Godot 侧没有战斗逻辑，`project.godot` 主场景与
> `MinimalRun.tscn` 一个字节未改，`CardDeck.gd` / `card_rules.js` 的抽卡规则与黄金样本未改，
> `docs/design-freeze.json` 的 22 条冻结条目未改。本结果**不可迁移到实机**。

## 2. 三层分类（最重要的一节）

编译器按 `params` 的**键名**逐条分类，一张卡可以同时命中多层。72 张卡共 **129 个 params 键**：

| 层 | 键数 | 含义 | 去哪了 |
|---|---|---|---|
| `battle` | **28** | 卡面 text 与参数语义明确，网页战斗内核能真实结算 | `battle_sim.js` 的 `this.fx` |
| `deck` | **42** | 五上界变量 / 封牌 / 舍牌 / 候选 / 局外经济传承 | `card_rules.js` / `CardDeck.gd` 已有或归属；本轮**不重复实现** |
| `none` | **59** | 语义需设计确认、条件系统未建、或网页验证层没有对应系统 | **如实列为未映射**（66 类键，每条带理由） |

**有战斗层效果的卡：26 / 72**（不是 72）。这是真实覆盖率，**不得塞凑数**。
其余 46 张在网页面板上会写明「本卡无战斗层效果」并逐条列出未映射原因。

### 2.1 逐卡核对后确认生效的映射（节选）

| 卡 | 参数 | 战斗里可观测的变化 |
|---|---|---|
| 破云式 | `split:2, per_hit:0.6` | 一次技能发 2 个 `damage_applied`，日志 `第1/2段 / 第2/2段`，**总伤不变** |
| 雷篆重描 | `hits:2, split_total:true` | 2 段均分（网页无「落点」坐标系统，用同一目标分段近似） |
| 拳风连震 | `extra_hit:0.3` | 追加 1 段 30% 伤害，单次峰值不变 |
| 破域 | `pierce_defense:0.05` | 目标 `defense` 降低 → 实战伤害变大 |
| 淬精 | `crit_rate:0.03` | 暴击率 +3% |
| 凝丹 / 寿元 / 舍身 | `hp_max` | 快照 HP 上限 300 → 324 / 360 / 255（绝对值与比例分开） |
| 灵脉拓宽 / 无根 | `spirit_max` | 灵力上限变化 |
| 步摇 | `move_speed:0.05` | 走位变快 |
| 轻灵 / 无根 / 舍身 | `skill_cd` | CD 系数（轻灵：0.8 s → 0.768 s） |
| 省息 | `spirit_cost:-0.08` | 技能灵耗降低 |
| 灵潮 | `free_cast:true` | 灵力满时下一技能不耗灵 |
| 护体 | `shield_max:20` | 每层开局护盾 20；受击先扣盾并发出 `shield_absorb` |
| 铁皮 / 混元 / 守拙 | `defense_rate` | 玩家承伤降低 |
| 铁骨 | `flat_reduce:6` | 每次承伤固定减 6 |
| 避水 | `invuln:0.5` | **受击后**无敌窗口 0.2 → 0.5 s（不是闪避无敌） |
| 舍利 / 转生 | `revive_hp` | 首次阵亡以 30% / 20% HP 复活，本局不结束 |
| 聚灵阵 | `on_kill:3` | 击杀回灵 |
| 逆转回灵 | `per_hit:2` | 每次命中回灵 +2（按卡 ID 精确映射） |
| 截取 | `on_hit:4` | **玩家受击**回灵 +4（不是命中回灵） |
| 天人感应 | `reveal:true` | 信息层标记，不改判定 |

### 2.2 逐卡核对后**明确不模拟**的（避免伪造）

| 卡 / 键 | 为什么不做 |
|---|---|
| 回春化刃 / 金刚怒目 `convert` | 卡面是「**治疗量 / 已吸收量 → 下一次技能伤害**」，不是吸血。一度被误映射成命中回血，核对 text 后撤回 |
| 聚息 / 珠链 / 清露 `regen` | 卡面全部是「**脱战后**」或「连续 3 次命中」才生效，聚息更明确写「战斗中不生效」；脱战判定未定义 |
| 截取 `on_hit` | 同一 hook 下「截取」指玩家**受击**、「逆转回灵」指**命中**，参数名相同语义相反 → 改为按卡 ID 映射 |
| 破云式 `per_hit` | 是分段倍率（由 `split` 处理），不是回灵量 |
| 剑意凝形 `pierce` | 需「剑修标签 ≥2」条件 + 贯穿路径判定，标签系统未建 |
| 五行逆克 `pierce_defense` | 只对带「铁壁」**词缀**的敌人生效，词缀系统未建 → 该卡不生效 |
| 反涌 `shield_cap` | 是「灵力溢出转护盾」，网页没有溢出结算，不固定发盾 |
| 丹香 `spirit_cost` | 卡面限定「回春诀灵耗减半」，本验证层 4 技能槽不按技能区分，不全局套用 |
| `dot_stack` / `stack` / `damage` / `heal` / `skill_slots` / `MetaSave.*` | DoT 每跳伤害未给值 / 语义兼作代价与倍率 / 需 Q17 UI 设计稿 / 属局外系统 |

**R54（本轮新发现）**：破云式卡面写「飞剑分裂为 2 道，单道 ×0.6，**总伤不变**」，
但 `split:2 × per_hit:0.6 = 1.2`，与「总伤不变」不自洽。
本验证层**以冻结卡面 text 为准**按 `0.5 / 0.5` 均分，并在 `notes` 与网页面板显式标 ⚠️，
**待设计确认**，不自行挑一个数值当结论。同类口径提示另有 4 条（落点近似、玩家减伤近似等）。

## 3. 接入方式与「默认行为不变」保证

`battle_sim.js` 新增 `emptyCardMods()`（字段与 `card_effects.js` 的 `defaultMods()` 一致，
由 `verify_card_effects.js` 断言键集合防漂移）与 `applyCardEffects(effectSet)`。

- 所有新分支都由 `this.fx` 的零值 / false 守卫：默认 `segmentRatios=[1.0]`、
  `cdScale=1`、`spiritCostScale=1`、`shieldMax=0`… → **与第 20 轮逐字段一致**（44/44 断言全绿）。
- 断言另跑 120 tick 对比「未接效果」与「接空 EffectSet」的 snapshot，逐字段相同；
  空效果甚至不把 `cardEffects.active` 标成 true（本轮修掉的真实差异）。
- 改动点只在 `startStage` / `tick` / `tryCast` / `updateEnemies` / `snapshot`，
  **没有改** `CAP_*` 五上界、`damageFormula()`、`STAGES`、`SKILLS`、`PROPOSAL`。
  全 72 卡叠加后 `damageFormula` 峰值仍是 **3996 < Boss 4400**。
- 新增事件：`card_effect`（效果触发）、`shield_absorb`、`revive`；
  `damage_applied` 在多段时带 `segment / segments`。

## 4. 网页怎么点（不需要 Godot）

双击 `previews/web-demo.html`（`file://` / 单文件 / 零依赖 / 无网络）：

1. **① 横版战斗 → 🧪 预置机制卡组（演示注入，非抽卡）**：一键注入破云式 / 护体 / 舍利 / 铁皮 / 轻灵，
   立刻看到多段命中飘字、护盾吸收、减伤、CD 变化；右侧「本局生效卡牌效果」逐卡列条目、口径提示与未映射键。
2. **正常闭环**：清层 → 🎴 去选一张卡 → ② 选卡 → 自动回 ① 下一层。
   本局已选卡（`pickedLog`）是唯一真源，重开一局自动清空，不残留。
3. **🧪 共享池 +150** 仍是「只看伤害公式因果」的人造输入；两个 🧪 按钮都**明确标注不经过抽卡规则**，
   不改候选 / 种子 / 卡库 / 冻结数值。
4. **调试 URL**：`?cards=card_id1,card_id2` 直接预置指定卡；`?battle=N` 进第 N 层；
   `?freeze=TICK` 冻结便于截图；`?autolink=1` 自动跑清层→选卡闭环；`?pool=N` 等价共享池注入。

无头 Chrome 实跑（`?cards=...&freeze=75`）日志摘录：

```text
🎴 本局已选 5 张 / 战斗生效 5 条 · 归抽卡层 3 条 · 未映射 2 条
🎴 多段命中：50% + 50%
  thunder_talisman → mob_shanxiao:0 21 第1/2段 [pool=0 combo=1.08]
  thunder_talisman → mob_shanxiao:0 21 第2/2段 [pool=0 combo=1.16]
  🛡 护盾吸收 9（护盾剩余 11）
  🛡 本次伤害被护盾完全吸收（HP 未损失）
```

## 6. 边界（不得省略）

- 本轮的 EffectSet 是**网页验证层的可视化口径**，不是 `docs/01` 冻结规格，不是平衡结论，
  **不迁移到 Godot 实机**；Godot 侧依然没有战斗场景、没有把任何规则挂进 `.tscn`。
- **卡牌跨端黄金样本仍只覆盖抽卡规则**（25/25）；战斗没有跨端黄金样本，
  不能说「网页战斗测过 = Godot 战斗一致」。
- 46 / 72 张卡在网页战斗里没有可观测效果，是**如实未映射**，不是「已实现但没显示」。
- R51 的 12 项 PROPOSAL 占位（技能 CD / cost / HP / 敌人伤害 / 暴击率等）**仍未确认**；
  本轮的「CD −4%」「护盾 20」等是**在 PROPOSAL 基线上做的相对变化**，不是新增冻结数值。
- R50 Boss 素材仍为空（第 5 / 9 层占位）；R52 Q17 仍未拍板，主菜单 / 战斗 UI 仍是职责原型，
  不是 `03` §7 的 6 界面可编辑设计稿。
- R9 字体授权 / R46 CJK 字形 / R48 卡面行宽 / R49 封牌 8 次上限仍待确认。
- **R54 卡面与 params 不自洽待设计确认**，本验证层只是选了以冻结卡面为准，不构成裁决。
