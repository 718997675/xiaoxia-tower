# 26 · 第 33 轮：UI 设计稿按视图联动对照层

> 增量文档，按「基线永不覆盖」原则新增；`docs/22`–`docs/25` 正文保留为历史快照。
> 本轮仍是**网页验证层**工作，不建 Godot 工程、不改冻结数值、不冻结设计。

## 1. 为什么这一轮做这个

`docs/00` §9 里剩余的实质欠债有三条：**R56 逐 tick 状态机跨端对齐**、46 张卡未映射条目、`@trace DF-xx` 补回指。前两轮（`docs/23` §3、`docs/25` §"下一步"）已把 R56 明确划在**拍板 Q17 之后**；46 张卡的 `convert` / `regen` / 条件类参数按 `docs/18` 口径「一律不猜测、待正式工程逐条确认」；`@trace` 回指也随正式战斗工程另建时补。三条都越过不了当前门禁，本轮不动。

真正确定能做、且延续用户「**我生成的 gpt-image2 稿子质量更高，务必好好利用**」诉求的缺口是：

第 31 轮把 `previews/ui/` 的 9 张 UI 稿资产化成了 `assets/ui/reference/` 116 张（9 整屏 + 9 个 16:9 底板 + 44 组件 + 6 图标带 + 48 逐格图标），并给了静态目检页 `previews/ui-reference-overview.html`；第 32 轮把 **A/B/C 组**的转录资源接进了实际可交互的横版战斗画面。但**这 9 张 UI 稿始终没进 `previews/web-demo.html`** —— 用户日常打开验证层看六个界面时，看到的仍全是第 20 轮手写 CSS，稿子只躺在一个单独打开的静态页里。

## 2. 一个必须先讲清的判断：不能把稿子贴进界面

9 张 `ui_*_panel.png`（960×540）是**含完整文字与布局的整屏设计稿**，不是纯底纹。切出的 44 个组件里，多数自带示例文案与写死数值：

| 组件 | 内含的写死内容 |
|---|---|
| `ui_02-towerhud_bar_hp.png` | 血条 + 数字 `276/300` |
| `ui_02-towerhud_bar_qi.png` | 灵力 `180/200` |
| `ui_04-result_result_panel.png` | `通关·第 9 层` / `修为 +180` |
| `ui_03-draft_card_01..03.png` | 完整卡牌名称 / 描述 / 数量徽标 |
| `ui_01-mainmenu_button_01.png` | 「开始入塔」成品按钮 |
| `ui_00-anchor_sigil_03.png` | 「机制改变」标注文字 |

若把这些直接贴到可交互界面上冒充血条 / 卡框 / 按钮，页面会显示**与 `battle_sim.js` 规则值不一致的假数值**，直接违反项目「任何数值都要能给出复算过程、不把示例写成结论」的纪律，也会把 R55「外部模型出图只算参考稿」误当成已入库。

所以本轮采取**按视图联动的设计稿对照层**：稿子并排可见、随视图自动切换，但**不铺进任何 `section`、不替换任何交互组件、不参与任何规则复算**。这是「让稿子在使用路径里可见」与「不制造假数值」之间的唯一稳妥解，不是又堆一个静态页——静态页做不到切视图自动换稿。

## 4. 实现位置

全部改在 `tools/build_web_demo.py`（单文件生成器），产物 `previews/web-demo.html`：

- `load_images()`：按 `assets/ui/reference/ui_reference_manifest.json` 里 `kind == "panel16x9"` 取 9 张，**不用 `glob("ui_*_panel.png")`** —— 组件名如 `ui_04-result_result_panel.png` 也会匹配上，会多出 4 张。数量不等于 9 直接报错。
- CSS `.uiskinbar` / `#uiSkinImg`：设计稿是 LANCZOS 归一的 960×540，必须 `image-rendering:auto` 覆盖全局 `pixelated`，否则缩略被最近邻放大成锯齿；`object-fit:contain` 保证 16:9 不被拉伸。
- DOM `#uiSkinBar`：标题 + 稿数标签 + 下拉 + 开关 + 联动提示 + 图片 + 边界说明。
- JS `UI_SKINS` / `SKIN_BY_TAB` / `setUiSkin()` / `applyUiSkin()` / `applyUiSkinForTab()`：声明放在脚本前部，避免 `renderStatus()` → `browserSelfcheck()` 踩 TDZ；nav 点击回调里调 `applyUiSkinForTab(currentTab)`，所以 `?battle=5` 触发的 `switchTab()` 也会自动联动。
- 调试口：`?ui=off` 默认收起；`window.__setUiSkin` / `window.__getUiSkin` 供无头浏览器复验开 / 关两态。

`tools/final_selfcheck.py` 新增第 **35** 项 `ui_skin_r33`：逐字节核对 9 张 panel 的 base64 真在 HTML 里（防「只改文案不接真图」）、9 个 `UI_SKINS` 条目、6 条视图映射字符串、边界标注齐全、浏览器实时自检两条断言存在，并代跑 `build_web_demo.py --check` 与 `build_ui_reference_assets.py --check`。不写死图数。

顺手把第 34 项 `web_reference_art_r32` 的返回措辞补上「+ 第 33 轮 UI 设计稿对照 9 张」——它的 `n_img` 本来就是动态算的，只是列举项停留在第 32 轮，容易误读。

## 7. 边界（未解除，不得写成已通过）

- 对照层是**设计稿展示**，不是界面贴图、不是 `03` §7 的 UI 定稿；稿中文字 / 数值一律不作实机数值。
- `R55`：外部模型出图只算参考稿、不算入库资源；**Q17 未拍板**，稿中坐标为 **PROPOSAL**。
- `assets/ui/reference/` 的 44 组件 / 48 逐格图标仍是**候选资产**，未替换 47 个冻结图标 ID 与 10 张卡面；48 个图标与 `docs/icon-catalog.json` 的 ID 对位仍留待用户确认，本轮不猜测。
- **GUI F5 未跑、未接任何 Godot 场景、未改任何冻结数值**；`battle_sim.js` / `card_rules.js` / `card_effects.js` 规则实现一字未动。
- `docs/22`–`docs/25` 按基线不覆盖原则保留历史快照，其中 31/31、32/32、33/33、34/34 分别是各轮快照。
