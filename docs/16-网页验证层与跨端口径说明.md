## 2. R47：先统一随机源，否则「网页测过」没有意义

### 问题（改前）

`scripts/CardDeck.gd` 用引擎内置 `RandomNumberGenerator`（Godot 的 PCG32）。种子 `FNV-1a(run_id:stage)` 虽然是自实现、可跨端复算，但 **`randf()` 序列只有 Godot 自己能产出**。若网页另写一套规则，即使权重、卡库、过滤条件全部一致，逐层 `offer()` 结果也会不同——那么「网页测过没问题 → 再导入 Godot」就只是口头承诺，恰恰违背用户要的「可控」。

### 改法（改后）

| 项 | 改前 | 改后 |
|---|---|---|
| 种子 | `FNV-1a(run_id:stage)` | **不变**（`runA:1 = 4264777024`，断言仍固定该值） |
| 随机源 | `RandomNumberGenerator`（PCG32） | 自实现 **xorshift32**，每次 `offer()` 用 `run_seed(stage)` 重置 |
| `randf()` | 引擎内置 | `(_rng_next() >> 8) / 2^24`（高 24 位定点，避开浮点尾数差异） |
| 网页/Node | 无法复刻 | `tools/card_rules.js` 用位运算 `>>> 0` / `Math.imul` 逐位复刻 |
| 冻结数值 | — | **一个都没改**：卡库、权重、五上界、抽取规则、过滤条件全部原样 |

`CardDeck.gd` 新增 `_rng_reset` / `_rng_next` / `_rng_randf`，`offer()` 与 `_weighted_pick()` 改接自实现随机源。改后 Godot headless **仍 23/23 PASS**，峰值 **3996 < 4400**、守卫事件 **105**、违规 **0**。

> 为什么敢改：第 18 轮的 `tools/verify_card_rules.gd` **只写死了 FNV 种子值，没写死任何具体抽卡序列**（断言的是确定性、同类同层、8 层流程、红线等性质）。因此换随机源不违反冻结规格，只改变"哪一局抽到哪张卡"这一 PROPOSAL 层的表现。

## 3. 跨端一致性证据（可复算，不是口头保证）

命令链（按顺序）：

```bash
Godot --headless --path . --script res://tools/export_card_golden.gd   # Godot 出黄金样本
python3 tools/verify_cross_platform.py                                # Node 复算 + 落报告
python3 tools/build_web_demo.py                                       # 把同一份 JS 内嵌进网页
```

`export_card_golden.gd` 导出 5 个 run（`runA` / `runW` 无相 / `runB` / `runDemo` / `web-demo`）的 9 步逐层 `offered` / `seed` / `eligibleCount` / `pick_event` / 峰值 / 守卫事件 / 违规、12 个 xorshift32 `randf` 逐位样本、72 卡全叠加快照。`cross_platform_check.js` 用 `tools/card_rules.js` 复算比对，**25/25 PASS** → `docs/cross-platform-report.json`。

网页里内嵌的就是 `tools/card_rules.js` **全文**，`final_selfcheck.py` 有字节级同源断言；网页 ④ 还会在你打开页面时用这份实现**实时复算 `runA` 的 9 步**并与 Godot 黄金样本比对。三端（网页 / Node / Godot）用的是同一份规则代码，不是三份"照着写"的实现。

## 4. 浏览器内实证与抓到的真实缺陷

用本机无头 Chrome 实际加载 `file://` 页面（不是只看生成结果）：

- **7/7 浏览器内自检 PASS**：72 卡加载、确定性、8 层流程、封牌、72 卡全叠加峰值、网页复算==黄金样本、无相 2 选 1。
- **自动演示整局**：URL 加 `?autorun=1` 自动逐层跑，`s1…s8` 共 8 次选择全部落日志，结算显示「共 8 次选择 / 峰值 3996 / Boss 4400 / 违规 0」；`s6` 正确避开 `card_wuxin` 封牌卡，`s3/s4` 复现 `card_ningdan` 堆叠语义。
- **首屏截图**：`previews/web-demo-首屏截图.png`，三卡分离、卡框/纹样/中文/状态面板/按钮均正常。

本轮抓到并处置的 3 个真实问题（都不是崩溃，是口径或视觉）：

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 网页自检「8 层流程」FAIL，只跑了 2 层 | 第 2 层抽到 `card_sheli`（`stop_draw` 封牌），选后本局不再弹卡——**规则是对的，断言口径错了** | 自检主流程避开 `stop_draw` 卡以跑满 8 层，封牌另设独立断言；`verify_card_rules.gd` 的「一局恰好 8 次选择」措辞改为「本样例局 8 次（8 次是上限）」。记为 **R49** |
| 2 | 三张卡叠在一起只看到一张 | CSS 没给 `.card` 设 `left`，绝对定位元素全落到同一静态位置 | 按 `12` §2 补 `left = 80 / 192 / 304`；截图复验通过 |
| 3 | 效果描述溢出卡面、压住信息条 | `12` §2「最多 3 行 × 每行 ≤14 汉字（10 px）」与 96 px 卡宽不自洽（14×10 = 140 px > 86 px 文本区） | 网页按实际像素容量 **8 字/行 × 3 行截断**，全文在图鉴详情可见；规格矛盾记为 **R48**，待 4× 实机复核，**不擅自改冻结规格** |

另有一项**环境诊断**：Godot 4.7.2 headless 下，内置默认字体 ASCII 覆盖 10/10、简体中文 **0/30**，`SystemFont` 在无头环境也取不到系统字体（FreeType 报 `font: ''`）。按 `12` §8「字体定稿前只验位置与行数、不做字形验收」，本轮**不引入任何字体资产、不碰 R9**，改用「类别纹样 + 类别色条 + 稀有度点阵 + 卡框层次」做无字形冗余编码；记为 **R46**，需 GUI 核实。

## 6. 边界（不得越界解读）

- 网页是**验证层，不是游戏本体**：没有战斗、没有存档、没有特效、没有 Godot 渲染，也没有把 `CardDeck.gd` 挂进任何 `.tscn`。
- ② 的 `image-rendering: pixelated` 只是 CSS 模拟 Nearest / 整数倍缩放，**不等于 Godot 实机渲染**；像素硬边、480×270×4 对齐、朝右镜像不穿帮、阴兵对比度仍须用户按 `docs/13` §12 在 GUI 按 **F5** 目检（R37 / R22）。助手**从未跑过 GUI**，不得标「已通过」。
- 网页用系统预览字体；卡面 PNG 依旧**不含文字**，实机点阵字授权 R9 未结案。
- 全部权重、概率、层数曲线、伤害数值均为 **PROPOSAL / 待实测**；本轮只证明「可复算 + 能看到」，不证明「平衡」。
- 本轮 **0 积分 / 0 张源图 / 未跑 GUI / 未改 `project.godot` / 未改 `MinimalRun.tscn` / 未改冻结数值**。
- 工程结构自检报告 `docs/godot-project-check.json` 仍是第 15 轮历史证据，检查器脚本不在工程内故未重跑。

## 7. 导入 Godot 前的检查清单（给用户）

1. 双击 `previews/web-demo.html` → ① 点「▶ 自动演示整局」，看 8 层候选数、峰值、红线、已选卡是否符合预期；④ 看 7 项浏览器自检是否全 PASS。
