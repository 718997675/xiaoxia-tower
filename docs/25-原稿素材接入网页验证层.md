# 第 32 轮：把 gpt-image2 回稿接进网页验证层的实际战斗画面

> 增量文档，不覆盖 `docs/22` / `23` / `24` 的历史快照。轮次基线：第 31 轮 33/33 PASS。

## 1. 为什么做这一轮

第 31 轮把 17 张 `*_palette24.png` 中的 16 张转录成了 `assets/boss/`（42 帧）、`assets/vfx/`（技能 36 帧 + overlay 10 帧）、`assets/bg/`（16 层 + 4 合成图）与 `assets/ui/reference/`（116 张）。但这些资源当时只躺在磁盘、静态目检页和 JSON 报告里，**没有任何实际可交互的画面在用**：

- `previews/web-demo.html` 的横版战斗仍跑第 20 轮口径：CSS 渐变天空 + 多边形远山 + 纯色地面，Boss 用 `mob_jian_hun` 放大 96px 占位。
- 生成器 docstring、战斗视图说明、风险表 R50、战斗内核注释、战斗日志，都还写着「`assets/boss/` 为空 / Boss 素材未产」。
- 浏览器内实时自检有一条写死 `vfx === 16`，而第 29 轮起 vfx 已是 36 帧 —— 这条断言实际上会 FAIL，只是静态自检从来不实跑浏览器 JS，所以一直没暴露。

本轮目标：**让用户在真实可玩的战斗画面里看到自己的回稿**，同时把这些过时口径一次性收干净。不改冻结数值、不建 Godot 场景、不等 Q17 拍板。

## 3. 具体改动

### 3.1 `tools/build_web_demo.py`

- `load_images()` 增载 `assets/boss/*.png`、`assets/vfx/overlay/*.png`、4 张 `*_composite.png`（语义 key `bg_normal` / `bg_rest` / `bg_high` / `bg_boss`）。新增动态自洽：Boss PNG 数必须等于 `assets/boss/*.json` 的 `frameCount` 之和且 ≥42，overlay 必须 10 帧，4 张背景必须齐。
- CSS 新增 `.arttoggle` / `.bbgart` / `#battleStage.art-ref …`：原稿模式隐藏不透明的 `.bsky` / `.bfar` / `.bground`，否则它们会把背景图整片挡住；`.bgline` 保留作地面基准，改浅色。
- DOM 在 `#battleWorld` 最前插入 `<img id="bBgArt" class="bbgart">`。
- JS 新增 `refArt`（默认 true，`?art=placeholder` 为 false）、`BG_BY_TYPE`、`setArtMode()`、`applyStageBg()`、`bossFrameKey()`；`renderBattleUi()` 在层号变化时换背景，敌人渲染按 `e.boss && refArt` 切真帧与 128px。
- 修正 docstring、战斗视图说明、风险表 R50、战斗日志，以及浏览器内实时自检的帧数口径。

### 3.2 `tools/battle_sim.js`

**只改头部注释，未改任何一行规则逻辑**（冻结数值 / STAGES / SKILLS / damageFormula / 状态机全部原样）。原注释「第 5/9 层 Boss 素材尚未产出（assets/boss/ 为空）」已不符合事实，改为说明：规则层仍保留 `BOSS_PLACEHOLDER`（冻结规则不动），像素呈现由展示层决定，Godot 正式战斗工程仍未接入。

因为网页内嵌的是 `battle_sim.js` **全文**（`c_web_demo_r19` / `c_battle_demo_r20` 都断言字节同源），改注释后必须重建网页产物，`--check` 才能一致。

### 3.3 `tools/final_selfcheck.py`

- 新增第 **34 项** `web_reference_art_r32`：逐字节核对网页内嵌的 4 张背景、首末各 1 帧 Boss、首末各 1 帧 overlay 与磁盘 PNG 一致（防「只改文案不接真图」）；核对模式标记齐备、旧口径已清除、实时自检不再写死 `vfx 16`；并代跑 `build_web_demo.py --check`。内嵌图数量断言按「159 旧基线 + 磁盘实际 Boss/overlay 帧数 + 4」动态计算，**不写死 235**。
- `c_battle_demo_r20` 的边界标记列表原本写死要求网页出现「Boss 素材未产」。现在这是句假话，按「不能为了过断言保留假话」的口径换成 `Q17` / `PROPOSAL` / `assets/boss/` / `不接 Godot 场景` / `不是游戏本体`，并显式断言「Boss 素材未产」不再出现。

## 5. 边界（不要误读成「游戏做完了」）

- **仍是网页验证层**：CSS `image-rendering:pixelated` 只模拟 Nearest，不等于 Godot 实机渲染；`project.godot` / `MinimalRun.tscn` / 任何冻结数值一个字节未改；Q17 未拍板、GUI F5 未跑、Godot 侧仍无战斗场景。
- `BOSS_PLACEHOLDER` 在 `battle_sim.js` 规则层保留（冻结规则不动），网页只是**展示层**按 `snapshot.type` 另取真帧；`snapshot.placeholder` 仍为 true，日志已按模式分别如实表述。
- 命中瞬间的「白色人物剪影 + 1px 黑描边」是 `flash_white()` 生成的 **hit 闪白帧**，是像素游戏惯例，不是破图；截图恰抓在该帧。
- HUD 底衬是验证层临时可读性兜底，**不是 `03` §7 的可编辑 UI 设计稿**；原稿背景的 R22 亮度代理超 30% 的 3 个场景仍按第 31 轮口径登记在 `docs/bg-layers-report.json` 的 `knownExceptions`，未调色、未伪造 PASS。
- `assets/ui/reference/` 的 116 张仍是候选资产，**本轮没有替换** 47 个 R23 冻结图标与 10 张卡面；UI 组件裁切框、48 个逐格图标与 `icon-catalog.json` 的 ID 对位仍需人工目检确认。
- 四深度层视差系数 0.15 / 0.45 / 1.0 / 1.30 仍是 PROPOSAL；本轮背景用的是**四层合成图**，未做逐层视差滚动。
