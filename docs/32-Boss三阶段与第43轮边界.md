# 32 · Boss 三阶段接入战斗与第 43 轮边界

> 用户指令：「继续下一步」。
> 本轮把第 41 轮可玩本体里「Boss 打到底都一个样」的缺口补上——
> 两个 Boss（锁血判官 / 天梯之主）按血量比切三阶段，切阶段有真帧变身 + 飘字 + HUD 阶段标记，

> 状态：**PROPOSAL / 可玩原型表现层 / headless 已验证 / GUI 画面未目检 / 不得当作平衡结论**。

## 0. 一句话

第 41 轮的可玩闭环里，第 5/9 层的 Boss 与普通怪共用同一套 AI：
只有 HP 被均分成一个大数字、`boss:true` 决定帧尺寸 128，
血量从 100% 掉到 0 之间没有任何行为变化。
用户第 34 轮的设计诉求是「每张卡 / 每个设计点都要突出、不能有重复感」，
Boss 同样是战斗高潮点，三阶段是横版战斗最直观的「打得有层次」。
网页验证层（`tools/battle_sim.js`）第 20 轮起已定义阶段划分并发 `boss_phase` 事件，
本轮把**同一划分**接进 Godot 侧 `StageView`，并补上网页没有的表现层战斗增强。

## 2. 跨端口径（R56 边界，不是逐帧一致）

- 阶段划分**与网页完全一致**：血量比 `> 0.66` → 阶段 1，`> 0.33` → 阶段 2，否则阶段 3；
  Boss 初始 phase=1，普通怪 phase=0。出处 `tools/battle_sim.js` 的 `ratio > 0.66 ? 1 : (ratio > 0.33 ? 2 : 3)`。
- **Godot 侧新增、网页没有的部分**：阶段递增的伤害 / 出手 / 移速系数 + skill 变身真帧 + HUD 阶段标记。
  网页的 `phase` 目前只用于事件与快照标记，不改变战斗数值。
- 因此 **本轮不构成「网页测过 = Godot 一致」**：R56 逐 tick 状态机仍未跨端对齐，
  阶段战斗增强是 Godot 表现层 PROPOSAL，不得反推到网页、也不得写进冻结规格。

## 3. 阶段数值与落点（全部 PROPOSAL / 表现层，非平衡值）

| 阶段 | 血量比 | 伤害系数 | 出手间隔系数 | 移速系数 | 阶段名 |
|---|---|---|---|---|---|
| 壹 | > 0.66 | 1.0 | 1.0 | 1.0 | 壹·镇 |
| 贰 | 0.33–0.66 | 1.15 | 0.85 | 1.10 | 贰·狂 |
| 叁 | ≤ 0.33 | 1.35 | 0.70 | 1.25 | 叁·殁 |

- 系数集中在 `RunConfig.BOSS_PHASE_ATK_SCALE / BOSS_PHASE_ATK_INTERVAL_SCALE /
  BOSS_PHASE_MOVE_SCALE / BOSS_PHASE_LABEL`，标 PROPOSAL，非冻结、非平衡结论（R51）。
- 落点：`StageView._spawn_enemy()` 初始化阶段并加载 skill 帧；
  `_cast()` 扣血后调 `_check_boss_phase()`；`_tick_enemies()` 按阶段槽位缩放伤害 / 出手 / 移速；
  `snapshot()` 暴露 `boss_phase`；`RunHUD.update_state()` 显示阶段名。
- **非 Boss 零影响**：`_boss_phase_slot()` 对 `boss=false` 返回 0，三张系数数组首项均为 1.0，
  第 41/42 轮行为逐字段不回退。
- 阶段只升不降：回血（如回春诀 / 卡牌回血）不会让 Boss 退回低阶段。
