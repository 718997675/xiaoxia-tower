# 12 · 卡牌 UI 规格（像素国风）· v0.1 PROPOSAL

> 配套：`docs/11-塔层三选一卡牌系统.md`、`docs/buff-card-library.json`、`tools/build_buff_cards.py`、`assets/_preview/buff-card-preview.html`。
> 生效约束全部继承 `docs/04-像素国风规格修订.md`（480×270 × 整数 4 倍 = 1920×1080、24 色锁定、硬边无抗锯齿、`image-rendering: pixelated`）与 `docs/07-图标与挂件形状规范.md`（三层形状语法）。
> **状态：PROPOSAL。** 卡面 PNG 内不含任何文字；文字由 UI 文字层渲染。R9 字体仍未完成授权与缺字核验，实机替换前不得当作可用。全部尺寸为设计值，**待 4× 实机排版复核**。

---

## 1. 一句话设计原则

> **类别靠形状，稀有度靠边框层次 + 色段，状态靠角标点阵；颜色只做辅助，永远不作为唯一区分手段。**

这是 `04` R12 的直接延续：24 色板只有 6 组色相，72 张卡若靠配色区分必然脏。本稿把 `07` §1 的三层语法平移到卡牌：

| 层 | 承担 | 取值 | 玩家读到 |
|---|---|---|---|
| ① 卡框 + 类别纹样 | 这是哪一类效果 | **6 种剪影互不相同** | 「这是技能伤害 / 机制改变」 |
| ② 稀有度边框 + 色段 | 这张有多稀有 | 4 档：1 / 2 / 3 层线 / 断线 | 「凡品 / 灵品 / 仙品 / 劫品」 |
| ③ 4×4 角标点阵 | 状态与堆叠 | 1–4 个金点 + `xN` | 「几阶 / 可叠几次」 |

## 2. 尺寸与坐标（全部为 1× 逻辑像素）

| 项 | 值 | 4× 后物理像素 |
|---|---|---|
| 逻辑画布 | 480 × 270 | 1920 × 1080 |
| 单张卡 | **96 × 144** | 384 × 576 |
| 卡间距 | 16 | 64 |
| 三卡总宽 | 96×3 + 16×2 = **320** | 1280 |
| 三卡起点 x | **80**（居中） | 320 |
| 三卡 x | 80 / 192 / 304 | 320 / 768 / 1216 |
| 卡片 y | 52 → 196 | 208 → 784 |
| 顶部标题带 | y = 8 → 28 | 32 → 112 |
| 底部确认条 | y = 214 → 246 | 856 → 984 |

> 96×144 不是传统卡牌比例（约 2:3），是为了让 3 张卡在 480 宽里留足左右各 80 px 的 breathing room，同时卡高 144 在 270 高里不顶到确认条。所有坐标都是 4 的整数倍友好值，**不做亚像素位移**。

### 卡面分区（96×144）

| 区 | 坐标 | 内容 |
|---|---|---|
| 外框 | 0–95 / 0–143 | 1 px 墨 `#000000` 描边；稀有度决定内框层数 |
| ① 类别条 | y 3–15 | 左 8×8 类别纹样（x 5–12）+ 类别名（文字层，x 16 起） |
| ② 插画区 | x 6–89, y 19–75 | 宣纸底 + 居中 **24×24 纹样 ×2 = 48×48**（整数放大） |
| ③ 卡名条 | y 79–93 | 居中卡名（文字层，12 px 点阵字，最长 5 汉字） |
| ④ 效果描述 | y 96–126 | 最多 3 行 × 每行 ≤14 汉字（10 px） |
| ⑤ 信息条 | y 130–140 | 左：稀有度点阵；中：`xN` 堆叠；右：类别 chip |
| 右上角标 | x 86–89, y 3–6 | 4×4 金点阵，1–4 点表示稀有度阶 |

**卡面 PNG 不含文字**：类别名、卡名、描述、`xN`、按钮文案全部由 UI 文字层绘制。这样 72 张卡只需要 4 张卡框 + 6 张纹样共 **10 张小图**，换文字不用重出图，也避开 `07` §7.3 已定的「不内置自造像素数字 / R9 字体授权」纪律。

## 3. 24 色分配（不新增任何颜色）

| 用途 | 色值 | 组 |
|---|---|---|
| 页面底 / 遮罩（实色，不用半透明） | `#12161F` | 墨·暗 |
| 卡面底（凡品 / 灵品 / 仙品） | `#E8DFC8` | 宣纸·亮 |
| 灵品插画区底纹 | `#C9BFA3` | 宣纸·主 |
| 劫品卡面底 | `#7A2420` | 朱砂·暗（文字改 `#E8DFC8`） |
| 全部描边 / 分隔线 | `#000000` | 功能色 |
| 凡品边框 / 角标 | `#4A5568` | 墨·亮（第 1 段色） |
| 灵品边框 / 角标 | `#5FA8A0` | 青玉（第 2 段色） |
| 仙品边框 / 角标 | `#D9A441` + `#F2D089` 高光 | 金（第 4 段色） |
| 劫品边框 | `#C8453B` 断线 + `#E8806F` 点 | 朱砂（警示语义） |
| 机制改变类主纹样 | `#8A6FC4` | 紫（第 3 段色） |
| 选中 / hover 高亮 | `#D9A441` | 金 |

> 4 档稀有度借用 `04` §4 的 4 段色（墨 / 青玉 / 紫 / 金）语义，但把「紫」留给仙品的角标渐变、「劫品」改用朱砂断线 —— 因为朱砂在板内承担「警示」，比紫更贴合「有代价的强卡」。**色相仍是 6 组，未越界。**

### 6 类纹样（形状互不相同，颜色只是辅助）

| 类别 | 形状键 | 剪影 | 取自 |
|---|---|---|---|
| 技能伤害 `dmg` | `arc` | 横向弯月弧 + 剑尖 | `07` §2.2 `sword_qi` 同族 |
| 属性提升 `attr` | `column` | 三阶立柱（高低递进） | 数值感，不用箭头 |
| 机制改变 `mech` | `gear` | 六边齿轮 / 咬合齿 | `07` §2.2 `vajra_body` 六边形同族 |
| 资源灵力 `res` | `drop` | 水滴 + 两道波纹 | `09` §3 `lingquan` 同族 |
| 生存回复 `surv` | `shield` | 盾形 + 中缝 | `07` §2.1 装备盾框同族 |
| 构筑风险 `syn` | `knot` | 交叠双菱 + 中心结 | `09` §2.5 `gongjie` 同族 |

> 复用既有形状语言是刻意的：玩家在图标、词缀、灵韵、卡牌四处看到同族形状，能形成一致记忆，也满足 `06` §4 / R16 对「形状语言统一」的要求。**但同族不等于同形**：卡面纹样是 24×24 的独立绘制，与 16×16 / 32×32 图标不共用像素。

### 4 档稀有度（靠边框层次，不靠新增色）

| 档 | 边框 | 角标点数 | 卡面 |
|---|---|---|---|
| 凡品 common | 1 px 墨线，四角平切 | 1 | 宣纸底 |
| 灵品 rare | 2 px 青玉双线，四角云纹缺角 | 2 | 宣纸底 + 插画区暗纹 |
| 仙品 legend | 3 px 金线 + 金色云角，顶边金亮线 | 3 | 宣纸底 + 金色类别条 |
| 劫品 curse | **朱砂断线**（四边各留 1 处断点）+ 朱砂斜角 | 4 | 朱砂暗底 + 宣纸色文字 |

**为什么用「断线」而不是「更粗的框」**：劫品是有代价的强卡，断线在 1× 像素下也能一眼与普通卡区分，且不需要新颜色或半透明；同时呼应 `09` §2.5 `shiling`（断链三节）的视觉语汇。

## 4. 四种状态的像素规则

| 状态 | 表现 | 禁止 |
|---|---|---|
| 默认 | 卡框按稀有度，卡面在 y=52 | 无阴影、无渐变 |
| hover | **整卡上移 4 逻辑 px**（整数），底部 1 px 金基线，类别纹样亮阶 | 不做缩放、不做亚像素位移、不用 `box-shadow` 模糊 |
| selected | 金 `#D9A441` 双框 + 右上点阵全亮 + 底部确认按钮亮起 | 不用半透明覆盖层 |
| 已读 / 未读 | 未读卡右上角多 1 个 `#E8806F` 方点（配合 R33 的 12 s 窗口） | 不弹新手引导遮罩 |
| 前置未满足 | **不进候选**（生成时过滤），UI 不出现 locked 卡 | 图鉴里可用实色 `#C9BFA3` 压暗，不用 alpha |

> 像素风里「半透明」是脏色之源：所有压暗、遮罩、高亮都用**实色替换**，与 `04` §4「半透明像素 = 0」的质检口径一致。

## 5. 三选一界面布局（480×270）

```
y 8    ┌ 第 N 层 · 择一机缘                  已选 3/8 · 道行 +120 ┐
y 28   └ 一条 1px 墨亮分隔线 ───────────────────────────────────┘
y 52        ┌──────┐   ┌──────┐   ┌──────┐
            │ 卡 1 │   │ 卡 2 │   │ 卡 3 │      x = 80 / 192 / 304
            │96×144│   │96×144│   │96×144│
y 196       └──────┘   └──────┘   └──────┘
y 214   ┌ 1/2/3 切换 ────── [ 确认 (Enter) ] ────── Esc 查看已有卡 ┐
y 246   └ 底部 1px 金线（仅选中时亮）──────────────────────────────┘
```

- 背景：`#12161F` 实色，层间界面是独立场景，**不叠在战斗画面上**（避免半透明遮罩）。
- 顶部左右两道云纹竖线为可选装饰，程序化生成，不占卡面。
- 第 8 层后不弹；`card_sheli` / `card_wuxin` 生效后，顶部改显示「本局已封牌」并直接跳过界面，避免玩家以为卡住。
- 键盘：`1/2/3` 直选、`←/→` 切换、`Enter` 确认、`Esc` 打开图鉴/返回、`R` 换一批（**仅预览页**；实机重掷受 `02` P1-6 与灵石消耗约束，未开放）。

## 6. 图鉴视图（72 张全览）

| 项 | 值 |
|---|---|
| 顶部筛选行 | y 8–28：6 类别 chip + 4 稀有度 chip + 名称搜索框，全部实色、无圆角 |
| 网格 | 每行 4 张，卡间距 8 → `4×96 + 3×8 = 408`，x 起点 **36**；行高 152，纵向滚动 |
| 总行数 | 72 ÷ 4 = **18 行**（筛选后重排） |
| 卡片尺寸 | 仍为 96×144 **原尺寸**，不做 0.5× 缩放（像素风只允许整数倍） |
| 点击 | 展开右侧详情：效果全文、`params`、堆叠上限、互斥卡、实现钩子 |
| 筛选计数 | 右下角显示「N / 72」，与 `buff-card-library.json` 实时一致 |

> 图鉴是**开发/内测用的自检工具**兼玩家收集页，不是一期必需 UI；若工期紧可后置，不影响三选一主流程。

## 8. 字体（R9 未结案，必须写在规格里）

- 实机卡名 / 描述需要简中点阵字，`07` §6 检索到的 **凤凰点阵体 CC0 1.0**（12/16 px、7543 字符）是最干净候选，但**缺字、嵌入授权、商用条款三项最终核验仍未完成**；Zpix 商用收费且禁止修改/转换，**不得默认可用**。
- 因此卡面 PNG **一律不含文字**；`buff-card-preview.html` 用系统无衬线字体仅作排版预览，页面内明确标注「预览字体 ≠ 实机字体」。
- 字体定稿前，UI 文字层只做「位置与行数」验收，**不做字形验收**。

## 10. 边界

- 本文件是**规格提案**，不是冻结规格；用户确认的是「要设计卡片 UI」，具体坐标、色值、行数仍待 4× 实机复核。
- 未改 `04` / `07` 正文；未新增颜色；未引入圆角、渐变、模糊、半透明。
- Q1 未填、未建工程、未置 `frozen`；`design-freeze-draft.json` 仍 `frozen=false`。
- 全部尺寸、权重、时长窗口标**待实测**；`buff-card-preview.html` 只验证视觉与交互，不验证 Godot 渲染结果。
