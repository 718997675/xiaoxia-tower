## 2. 为什么必须补这个工具

第 25 轮做的 `check_ui_art.py` 是**界面图**口径：尺寸必须是 480×270 整数倍、纯白占比过高要 WARN、越界色 / 半透明 / 柔边。把它套到 A 组背景与 B / C 组 sprite 形状板上，结果必然是：

- 方图 / 1536×864 → `size_rule` FAIL（参考稿按 R55 本来就该豁免）；
- sprite 形状板**就该是纯白底**，却会稳定触发 `too_much_white` WARN；
- 真正要紧的东西一项没查：背景会不会把墨甲阴兵糊掉（`20` §2.3 R22）、四个深度带能否切开、overlay 中心有没有留白 ≥ 70%、两帧是不是只差 1px、五个状态有没有画齐。

第 27 轮对 A 组做的「深墨系 72.5% / 中央战斗区暗 34.0%」是**临时脚本**算的，口径没写进任何文件。这与项目「任何数值都要能给出复算过程」的方法论冲突，也是本轮最先补的欠债。

## 3. 固化口径（可复算，定义写进报告的 `definitions` 字段）

### 3.1 `scene` 模式（A 组塔层背景）

- **色组**：每个像素按欧氏距离归到 24 色锁定板最近色，再按组计数。
  - 深墨系 = 墨三阶 `#12161F` `#2A3140` `#4A5568` + 描边 `#000000`
  - 浅宣纸系 = `#8A8268` `#C9BFA3` `#E8DFC8`
- **暗像素**：24 色板中亮度代理 `0.299R+0.587G+0.114B < 60` 的色，实际为 `#000000` / `#12161F` `/` `#2A3140`。阈值写死在脚本常量 `DARK_LUMA_LIMIT`，换色板后口径仍可复算。
- **中央战斗区**：`x 20%–80% / y 35%–75%`（`20` §4.1 原定义）。
- **四深度带**：上 1/4 远景 / 中 1/2 中景 / 下 1/4 地面（`20` §2.3）。
- **`r22ProxyLevel`**：战斗区暗像素 ≥ 60% 记 `HIGH`、≥ 30% 记 `MEDIUM`，否则 `LOW`。**这只是回稿文件的亮度代理指标，不是实机对比度实测**，不解除 R22。

### 3.2 `sheet` 模式（B / C 组形状板）

| 检查 | 判定 | 依据 |
|---|---|---|
| 画幅 | 非 1:1 记 WARN（不据此拉伸 / 裁切） | `20` §4 B/C 组提示词 |
| 纯白底 | < 35% FAIL / < 50% WARN | `04` §3 sprite 稿纯白底 |
| 越界色 / 半透明 / 柔边 | **复用 `check_ui_art.py` 的冻结阈值**，不另起口径 | `04` §4 / `12` §4 |
| 1px 黑描边 | 描边黑像素 < 0.1% 记 WARN | `19` §1.1 |
| 网格 | `B-` = 1×2 / `C1-` = 2×2 / `C2-` = 5×2，按文件名前缀自动判；每格内容 < 1% 记 `empty_cells` FAIL | `20` §4 提示词 |
| 中心留白 | **仅 C2 overlay**：每格中央 60%×60% 区域内非白内容 > 30% 记 `center_negative_space` FAIL | `20` §4 overlay 提示词「内部留白 ≥ 70%」 |
| 两帧脉动 | **仅 C2 overlay**：同行两格内容量相对差 ≤ 25% PASS / ≤ 50% WARN / > 50% FAIL | `20` §4「只做轻微脉动，形状完全一致」 |

> **口径边界**：`sheet` 的阈值目前只用**合成图**验证过判定能力（8/8），真实回稿只到了 3 张；阈值是否偏松 / 偏紧要等更多回稿才能说，**待实测**。体检结果按 R55 是返工依据，**不是入库闸门**。

### 5.4 偏差（如实记录，本轮不返工）

1. **C1 右下六边形金罩**：中心留白被画成了**淡色人形轮廓**，而提示词写「罩内不画角色、内部留白」。中心仍是留白的、体检 `center_negative_space` 也不适用 C1，属**轻微语义偏差**，概念稿不入库，正式程序化特效阶段按 `20` §4 口径处理即可。
2. **B 组朝向**：两个 Boss 接近**正面朝向观众**，提示词写的是「正面朝右」。概念稿只用于定剪影与配色，正式 18 / 24 帧帧表另按 `06` §6 产，此处不改图。
3. **尺寸不是入库尺寸**：B 组 1024×1024 里每格约 512×512，与 `Q21=128`（Boss 单帧 128×128）不是一回事——本图是**概念稿、不入库**，不按 128 判。三张也都不是 480×270 整数倍，按 R55 豁免。
4. **C1 第 3 格扇形**与已有「横向弯月弧」同属弧形类别，但方向（贴地扇形 vs 水平弯月）与轮廓不同，目视可分；**是否算形状语言重复，待正式程序化特效阶段确认**，本轮不下结论。
5. **JPEG 交付**：三张原始均为 JPEG，压缩振铃把柔边率推到 78%–84%（吸附后归零）。与第 24 轮结论一致：画幅 / 格式是生成平台参数，提示词写不生效；后续如需换图仍建议导出 PNG。

## 6. 工具缺陷与修正（真实回稿校准出来的，保留追溯）

第一版 `sheet` 模式把「同行两格内容量差异」无差别当成了「两帧脉动」，于是：

| 回稿 | 首次判定 | 为什么错 |
|---|---|---|
| B Boss 立绘 | WARN（差 45.8%） | 两格是**两个不同 Boss**，提示词本来就要求塔主「明显更高更宽」，差异大是设计意图 |
| C1 技能形状板 | FAIL（第 1 行差 55.0%） | 2×2 是**四个不同技能**，同行两格是不同技能，不是同一状态的两帧 |

**改法**：`pair_is_pulse` 只在 `C2-` 前缀或 `5×2` 网格时为真；B / C1 记为 `kind=distinct`，只记录数值、不判等级。并补两例防回归自检：`distinct_b_1x2`（两个体量差很大的 Boss 必须 PASS）、`bad_pulse`（C2 同行差异过大必须 FAIL 且命中 `pulse_mismatch`）。修正后三张真实回稿 **3/3 PASS**，合成自检 **8/8 PASS**。

> 这条要留着：工具的判定语义必须**逐组**对齐提示词，不能因为「都是形状板」就共用一个规则。
