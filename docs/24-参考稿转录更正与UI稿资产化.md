# 24 · 参考稿转录更正与 UI 稿资产化（第 31 轮）

> 本轮是**纠错轮**，不是新功能轮。起因：用户看到第 29/30 轮交付后指出
> 「我用 gpt-image2 生成的，你全都没用吗，质量比你的高」，随后补充
> 「ui 目录下很多都是你可以用的素材，`*-gpt-image2_*` 也都是我生成的，务必好好利用」。

## 1. 错在哪

第 29 轮我把 `docs/03 §4` 的「AI 直出整图不算入库」**错误扩大**成「所有 AI 回稿都丢掉、用 Pillow 几何块逐像素重绘」：

- `tools/build_b3b4_assets.py`：605 行纯几何绘制，**没有读取任何一张 PNG**，报告里写 `0 张 AI 源图`；
- `tools/build_bg_layers.py`：440 行几何重绘，docstring 写「AI 原图绝不裁切当入库资源」；
- 文档里只留一句「参考构图/配色」，实际连参考都没读。

用户回稿本身已经是**硬边像素风 + 24 色吸附完成**：`docs/reference-art-report.json` 总 verdict `PASS`，
B 组 1×2 / C1 2×2 / C2 5×2 排版稿越界色 0%、柔边 0%；A2R 16:9 重出版补充句 9/9 PASS。
A2R 的远山云纹、A4 的殿堂金饰、B 组两个 Boss 的甲胄纹样、08-icons 的六类图标，
细节量确实远超几何块。**判断失误在第 29 轮，不在用户回稿。**

正确做法不是「原图裁一刀直接入库」，也不是「全部丢掉重画」，而是
**以回稿为真实像素源做转录加工**：裁格 → 边界洪水去白底 → 等比缩放 → 24 色复核 →
帧变换 / 分带切层。既守住「直出整图不算入库」的工程约束，又保留回稿的全部美术质量。

## 3. 三个转录脚本

### 3.1 `tools/build_from_reference_art.py`（主转录器）

只覆盖已有 PNG 的**像素内容**，文件名 / 帧数 / frameSize / 引擎 JSON 契约一律不变，
因此第 29/30 轮的全部自检与网页产物无需改契约。

- **B3**：B 稿 1×2 裁格 → 边界洪水去白底 → **最大连通域剔除标注文字/格线** →
  脚底对齐缩到 128×128 → 基于立绘做像素级帧变换（呼吸 / 位移 / 前冲 / 亮阶 / 符文 /
  闪白 / 下沉），42 帧全部继承甲胄纹样。三阶段紫/金仍靠运行时换色，不重画。
- **B4**：C1 2×2 四格按「起手 0.55 → 扩张 0.78 → 峰值 1.0 → 消散 0.86」派生 16 帧；
  C2 5×2 十格直接对应 `shield/elite/burn/chill/affix` 各 2 帧。
  **`vfx_hit` 没有对应回稿（C1 只有 4 格）**，保留第 29 轮程序化 4 帧并在报告标注。
- **背景**：16:9 归一 → LANCZOS 到 480×270 → 24 色吸附 → 按 y 带
  `[0,68) [68,202) [202,270)` 切 L1/L2/L3（带外全透明），底部条带深色前景提到 L4。
  保真版深色多，L4 取用行数按「从最下一行往上累加、面积 <9.5%」动态收紧，
  未提到 L4 的深色像素留在 L3，合成画面不变。

### 3.2 `tools/build_ui_reference_assets.py`（UI 稿资产化）

九张 UI 稿全部纳入，产出 `assets/ui/reference/` 共 **116 张**：

| 类型 | 数量 | 说明 |
|---|---|---|
| `full` | 9 | 原尺寸、去水印、24 色复核 |
| `panel16x9` | 9 | 居中裁 16:9 → 960×540 整屏底板（缩放后二次吸附） |
| `component` | 44 | 边框层次 / 纹样 / 按钮 / 血条 / 卡框 / 详情面板等 |
| `iconRow` | 6 | 08-icons 六类整行图标带 |
| `iconCell` | 48 | 逐格图标（六类 9/4/12/9/8/6，等分 + 内容 bbox 精修） |

独立目检页 `previews/ui-reference-overview.html`（单文件零外部请求）。
**裁切框是相对比例估算值，需人工目检微调**，报告里如实标注，不冒充精确对位。

## 4. 口径修正（两处，都不是「改数字糊过去」）

### 4.1 默认入库改为原稿保真，不替用户改配色

第一次跑主转录时，我为了让既有 `R22` 硬断言通过，把深墨按 24 色板阶梯提亮一档
（`#12161F → #4A5568`、`#2A3140 → #8A8268`）。这**又是在擅自改用户的图**，撤掉：

- 默认入库 = **原稿保真**；`--tuned` 才输出可选调和版；
- 两版都留档在 `assets/_preview/reference_faithful_*.png` 与
  `reference_harmonized_*.png`，并排对照图 `reference_vs_geometric.png`；
- 原稿战斗区暗像素比超 30% 的三个场景（`bg_normal` / `bg_high` / `bg_boss`）
  在 `docs/bg-layers-report.json` 的 `r22Disclosure.knownExceptions` **如实登记**。

### 4.2 `final_selfcheck.c_assets_r29` 的 R22 断言改为「如实、可复算」

原断言 `need(gt["combatDarkUnder30PercentAll"])` 把「回稿亮度代理」当硬门禁；
报告自己都写着「只是回稿文件的亮度代理，不是实机对比度实测」。改为：

- 核对 `r22Disclosure.shippedMode` 存在；
- 逐场景核对 `combatDarkRatioShipped` 与磁盘复算值一致（±0.02）；
- 核对 `combatDarkUnder30Percent == (实测值 < 0.30)`，**防止伪造 PASS**；
- 若有未达标场景，核对 `knownExceptions` 与实际未达标集合**完全相等**；
- `l4Under10PercentAll` 仍是硬门禁，未放宽。

### 4.3 新增第 33 项 `ui_reference_r31` 防复发

专门把「源稿覆盖率」变成机器可复算的硬断言：17 张 palette24 必须取用 16 张、
唯一未取用必须是已登记理由的 A2 旧版；两份转录报告引用的源稿必须真实存在；
主转录脚本必须含 `load_ref`（防退回几何重绘）；两份 B3/B4/背景报告必须声明
`gpt-image2` 来源；UI 清单 ↔ 磁盘 ↔ 目检页三方一致；
**`assets/ui/icons` 的 47 个冻结 ID 与 `assets/ui/cards` 的 10 张卡面不得被替换**。

## 6. 边界（一个都没放宽）

- 所有资源 `status` 仍是「**待目检与合规确认；不得直接入库**」；
- **Q17 未拍板、GUI F5 未跑、正式战斗工程未建、未接任何 Godot 场景**；
- 特效 / overlay 运行时仍按 Q24 走程序化 shader，PNG 仅形状样板；
- 背景视差系数 0.15/0.45/1.0/1.30 仍是 PROPOSAL 待实测；
- `check_ui_art.py` 既有的方图 `size_rule` FAIL / 柔边 WARN 是第 24–28 轮已知状态，
  本轮未改、未伪造 PASS；
- 方图 A1/A3 与 9 张 UI 稿的 16:9 归一为居中裁切，**会损失上下内容**；
- `assets/ui/reference/` 是新增候选目录，**不替换** 47 个 R23 冻结图标与 10 张卡面；
  08-icons 的 48 个逐格图标与 `docs/icon-catalog.json` 的 ID 对位需人工确认；
- 第 29 轮几何版联系表留档为 `assets/_preview/*_geometric.png`，`docs/22` / `docs/23`
  正文按基线不覆盖原则未改动，其中的 31/31、32/32 是历史快照。
